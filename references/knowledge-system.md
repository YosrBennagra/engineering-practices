# Knowledge-system map

This repository deliberately covers **professional engineering practice**, not deep implementation domains.

| Repository | Primary responsibility |
|---|---|
| [software-engineer-roadmap](https://github.com/YosrBennagra/software-engineer-roadmap) | Master learning index and order |
| [computer-science-fundamentals](https://github.com/YosrBennagra/computer-science-fundamentals) | Algorithms, OS, networking, data structures, runtimes |
| [programming-principles](https://github.com/YosrBennagra/programming-principles) | Construction principles, clean code, OOP/FP principles |
| [java-mastery](https://github.com/YosrBennagra/java-mastery) | Java language/JVM depth |
| [spring-mastery](https://github.com/YosrBennagra/spring-mastery) | Spring ecosystem depth |
| [angular-mastery](https://github.com/YosrBennagra/angular-mastery) | Angular/frontend framework depth |
| [design-patterns](https://github.com/YosrBennagra/design-patterns) | Pattern catalog and application |
| [software-architecture](https://github.com/YosrBennagra/software-architecture) | Architectural styles, boundaries, quality attributes |
| [system-design](https://github.com/YosrBennagra/system-design) | Scale/distributed design |
| [testing-engineering](https://github.com/YosrBennagra/testing-engineering) | Testing strategy and techniques |
| [devops-platform-engineering](https://github.com/YosrBennagra/devops-platform-engineering-) | CI/CD, containers, Kubernetes, platform engineering |
| [application-security](https://github.com/YosrBennagra/application-security) | Secure design, vulnerabilities and security controls |
| [observability-reliability](https://github.com/YosrBennagra/observability-reliability) | Telemetry, SLOs, incidents, reliability techniques |
| [engineering-toolbox](https://github.com/YosrBennagra/engineering-toolbox) | Practical reusable tools/scripts/workflows |
| **engineering-practices** | Planning, review, delivery, migration, ownership, communication and engineering judgment |

The same real engineering scenario can link to several repositories. For example, a risky database migration belongs here for **planning, sequencing, compatibility and rollout practice**, while transaction semantics, database internals, test technique, infrastructure and observability depth belong elsewhere.
