# Scope boundaries and remaining professional-engineering gaps

## What this repository owns

This repository fills the cross-cutting professional layer that technical topic repositories usually leave fragmented:

- translating ambiguous work into executable engineering plans;
- managing uncertainty, risk, sequencing and change size;
- author/reviewer behavior around pull requests;
- durable technical decision workflows;
- legacy change, migration and compatibility thinking;
- release exposure and rollback reasoning;
- debugging and production ownership as engineering responsibilities;
- collaboration mechanics across product, QA, frontend, backend and platform;
- precise technical communication, feedback and mentoring;
- senior/staff judgment about complexity, leverage, maintenance cost and continuous improvement.

## What this repository intentionally does not duplicate

- Language/framework mechanics → Java, Spring and Angular mastery repositories.
- SOLID/DRY/coupling/cohesion and low-level programming principles → programming-principles.
- Pattern catalogs → design-patterns.
- Architecture styles and architecture quality attributes in depth → software-architecture.
- Distributed systems sizing/caching/partitioning/consistency in depth → system-design.
- Test pyramids, Testcontainers, mutation/property testing, load testing → testing-engineering.
- CI/CD implementation, Kubernetes, Helm, infrastructure/cloud/platform depth → devops-platform-engineering.
- Vulnerability classes, auth/security controls and threat modeling depth → application-security.
- OpenTelemetry, Prometheus/Grafana, SLO/error-budget mechanics and reliability depth → observability-reliability.
